# 双角色后台 + 用户ID配对设计(v3)

> 目标:用户端(用户网页)与管理端(管理台)双角色;配对采用"配对码 + 用户ID + 生成方确认"三重机制,无需令牌;
> 安全第一:防爆破、防注入、防越权、可审计。

---

## 1. 角色与入口

| 角色 | 入口 | 身份 | 页面职责 |
|---|---|---|---|
| 用户端(用户网页) | 配对码 + 用户ID + 生成方确认 | 用户ID 会话 | 显示当前用户ID下的设备、同步记录 |
| 管理端(管理台) | 账密(.env) | 管理会话 | 用户管理(短随机ID)、服务后台、统计、审计 |
| 同步设备(安卓/桌面) | 配对码 + 用户ID + 确认 | 设备ID(登记) | 剪贴板同步(开放) |

---

## 2. 核心概念:用户ID(设备组)

- 短随机固定 ID(如 K7M2F9QA),生成后作为该组设备的公共身份
- **可自行修改,全局唯一**(重复被拒)
- 组内任一设备生成的配对码,绑定成功后新设备自动加入该用户ID设备列表
- 未绑定设备生成配对码时,自动创建/分配用户ID,界面同时显示用户ID与配对码

---

## 3. 配对流程(三重机制:码 + 用户ID + 确认)

### 3.1 已绑定设备代邀请
~~~
设备G(用户X) → POST /api/pairing-codes → 生成码(归属用户X,10分钟)
新设备N     → POST /api/pair { pairingCode, userId, deviceId, deviceName }
              校验:码有效 + 码归属用户 == 输入用户ID → 创建待确认请求
设备G/管理台 → 收到请求通知(轮询/hub) → POST /api/pairing-requests/{id}/confirm
              确认 → 设备N.UserId = X,登记完成;拒绝 → 请求作废
设备N       → 轮询 GET /api/pair/status → pending / approved / rejected
~~~

### 3.2 未绑定设备首次配对
~~~
设备G(未绑定) → 生成配对码 → 服务端创建用户ID(短随机)并归属 G
              生成方界面显示:用户ID + 配对码
设备N → 输入 用户ID + 配对码 → G 确认 → G 与 N 同入该用户ID
~~~

## 4. 数据模型

~~~sql
Users (用户ID组)
  Id          TEXT PK        -- 短随机ID(如 K7M2F9QA)
  Name        TEXT UNIQUE    -- 可自行修改,不可重复
  CreatedAt   TEXT

Devices
  Id          TEXT PK        -- deviceId
  Name        TEXT
  UserId      TEXT NULL      -- 所属用户ID;NULL=未绑定
  Platform / Ip / Version / LastSeenAt / PairedAt

PairingRequests (配对码即请求)
  Id          INTEGER PK
  Code        TEXT UNIQUE    -- 8位,短时效
  GeneratorId TEXT           -- 生成方设备ID
  UserId      TEXT           -- 目标用户ID(生成方归属;未绑定则新建)
  DeviceId    TEXT           -- 申请方设备ID
  DeviceName  TEXT
  Status      TEXT           -- pending / approved / rejected / expired
  CreatedAt / ConfirmedAt
~~~

## 5. 权限矩阵

| 能力 | 用户网页(会话) | 管理台(会话) | 设备(无凭据,开放) |
|---|---|---|---|
| 剪贴板/历史/图片读写 | ✅ | ✅ | ✅(同步开放) |
| 查看本用户ID设备/同步记录 | ✅ | ✅ | ✅(登记) |
| 生成配对码 | ✅(归属自己用户ID) | ✅ | ✅(归属自己用户ID) |
| 确认/拒绝配对请求 | ✅(自己生成的) | ✅ | ✅(自己生成的) |
| 修改用户ID(唯一性校验) | ✅(自己的) | ✅(任意) | ❌ |
| 移除设备 | ✅(组内) | ✅(任意) | ❌ |
| 统计/健康/审计/用户管理 | ❌ | ✅ | ❌ |

## 6. 安全设计

- **三重准入**:配对码(限时一次性)+ 用户ID(组身份)+ 人工确认(生成方)——缺一不可
- **防爆破**:/api/pair 按IP限速(防枚举码+ID);/api/login 按IP+用户名 5次锁10分钟;timingSafeEqual
- **注入**:SQL全参数化;输入校验(长度/类型/白名单);路径穿越防护(已有)
- **XSS**:React转义 + CSP + nosniff + X-Frame-Options
- **传输**:TLS(自签证书支持);CORS显式白名单
- **会话**:用户网页会话/管理台会话仅内存+TTL,登出吊销(内部机制,用户不可见)
- **审计**:登录/配对/确认/移除/改名/清空 全记录(含IP)
- **部署**:非管理员运行、防火墙收口、.env 不入库

---

## 7. 实施步骤

1. 服务端:Users/PairingRequests 表 + 配对/确认/轮询接口(替换现有 token 签发)
2. 服务端:用户ID 修改接口(唯一性) + 权限矩阵中间件
3. 网页端:用户入口(输码+用户ID→等待确认→进入) + 设备/同步记录页(按用户ID)
4. 网页端:管理台用户管理(短ID列表/改名/删除)
5. 安全项:限速/审计/CSP/CORS
6. 桌面/安卓(另一会话):配对 UI 改"码+用户ID+确认"

---

## 8. 待确认细节(默认按建议实施)

- 用户ID修改:用户网页 + 管理台均可,唯一性强制
- 确认入口:生成方的用户网页/管理台页面(轮询或hub通知),桌面/安卓后续接入
- 设备移除:组内设备可在用户网页移除(登记层面);管理台可移除任意
- 配对码过期:10分钟;过期/被拒请求自动作废
